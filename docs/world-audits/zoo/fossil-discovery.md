## Shared authority and persistence

`ZooFossilState` is an additive format1 Zoo record. The server owns round ID, per-piece0–6 uncover progress, availability, holders, placements, four participant slots/epochs, accepted brush serials and bounded celebration age. Existing request receipts, world revision, visit and reliable command dispatch remain in use. Two pickups serialize to one holder. Incorrect/repeated placements cannot lose progress. Replay replaces the state once and increments the checked round; competing/late reset packets cannot edit the next round. Per-visit epoch and brush serial/rate guards reject stale contributions within a round.

Leaving, disconnecting, walking outside the corner, changing trails or travelling releases only that child's holder and slot. The revealed piece returns to its original tray patch. Everyone else's discoveries and placements remain. Entering with food refuses without canceling its ticket; pickup/food/toy guards prohibit carrying a fossil alongside food or another held item. Put the fossil down before choosing food; finish or explicitly return food before joining. Animal routines/feeding continue on the existing authority.

Restore preserves round/uncover/placed progress and normalizes participants, holders, brush timing and old celebration to resting. `nextEpoch` remains monotonic. Older saves without this field default to a new empty pilot while retaining existing Zoo state. No schema migration is needed: schema53/protocol3 remain; shared content changes78→79 because new authoritative commands/snapshots/rules require matching clients/server. Private offline and shared checkpoints use the established separate save branches. Unknown fossil formats fail rather than silently erase work.

No device install or live family server replacement. Installed463/content72 is retained and cannot serve this candidate's content79 without a separately authorized coordinated rollout.
