## Controls and ownership

Camera and album pictures occupy the lower-left safe corner, separate from top navigation, habitat props, the Games button and character picker. Camera opens one fixed whole-viewport frame with a large shutter, close X, album picture, saving message and latest thumbnail. Full-album feedback includes a filled album picture. No flash, zoom, filters, free camera, checklist, reward, video or new activity.

Album has six thumbnails per page and large page arrows. Open a thumbnail to view one full picture. Bottom arrows move that picture in album order. Leaf, heart, star and paw pictures add original editable UI-geometry stickers. Tap a sticker to select it; four large arrows move it among nine bounded positions. Remove sticker affects only the selected sticker. Six stickers per picture is a configurable source constant. Edits commit immediately; close returns directly to Zoo. Escape closes confirmation first, then editor to grid, then the overlay. Picture removal is separate from sticker removal, requires a pictured confirmation, and the last removed picture can be restored using **Undo remove**, including after restart. A subsequent removal retires the prior recovery picture. No silent replacement at the 24-photo limit.

Albums live only under `Application.persistentDataPath/ZooAlbums/<SHA-256 scope>/`. Shared scope uses the existing authoritative world ID and stable actor/profile. Private scope uses the existing private branch and saved actor; ordinary unpaired play uses its saved local actor. Shared and private prefixes are distinct. No transient connection/instance ID or character choice owns an album. No images or edits enter SoloSnapshot, commands, family recovery or gameplay networking. Another device does **not** automatically receive these pictures. The album explicitly says “Saved on this device only.” No device camera/microphone, OS photo gallery, permissions, export, account or upload was added.

Opening either overlay releases held local pointer/joystick input and stops only that child's locomotion. An existing food approach/destination and all authority-owned leases remain; closing resumes the retained approach. Local Zoo simulation continues behind the photo overlay, as does the shared authority. An opaque input shield prevents habitat taps from passing through. World/visit changes and pause/focus loss close the overlay. Focus loss subsequently uses the established game's input cancellation behavior. Other players keep their own UI and activities.

## Capture, storage and resources

The Zoo is a ScreenSpaceOverlay Unity UI canvas, with illustrated scenery, animated animals, depth-sorted characters and gameplay geometry under Board. The existing native verification camera-to-texture path established that the project's built-in renderer supports capturing this UI. Production uses a temporary dedicated camera and render texture, briefly renders the existing canvas in ScreenSpaceCamera mode, then restores render mode, camera, distance, graphics and layers in `finally`. This is a coherent current frame, without cloned behavior or desktop capture. All Text and graphics outside Board are excluded. Button graphics, feeder portraits and standing/pointer cues are excluded too. Habitat, actual animated animal pixels, visible characters, held food, care patches/brushes and water remain. Camera mode hides the same non-photo graphics locally so the framing preview corresponds to the saved composition. No shared time scale or scheduler changes.

JPEG originals use quality82 and a maximum long edge of960 pixels, preserving viewport aspect; thumbnail JPEGs use quality75 and a maximum long edge of192. Originals never change during sticker edits. Native landscape samples are960×443 and192×89. Each original ID is an application-generated GUID; every resolved image path is checked inside its album directory. Version1 metadata alternates between two complete generation-numbered JSON manifests, with same-directory temporary writes, durable flush and atomic replacement. Failed edits retain the previous in-memory/committed manifest. A single exact-ID capture journal recovers that capture's interrupted files. Removal retires only exact known prior recovery image/thumbnail paths, after both committed manifest slots stop referencing them. No game save or broad directory cleanup is used.

Malformed individual metadata is isolated; future/fully unreadable manifests open read-only. Missing/broken JPEGs show a placeholder instead of destroying the entry or other pictures. JPEG dimensions and file sizes are bounded before native texture decoding. Disk/write errors show a friendly message and retain committed data. Active storage is24 pictures plus one last-remove recovery picture; interrupted capture files are journaled. Healthy files associated with malformed metadata are preserved for recovery rather than swept away.

One capture can be active. Capture/readback/JPEG encoding stays on Unity's main thread; durable image and manifest writes run in one background task. Only six thumbnails or one full image are decoded for a current page/editor. Close/rebuild destroys those textures and UI; one tiny latest-photo confirmation is retained. Temporary render textures are released and original/thumbnail staging textures destroyed. Quiet shutter uses a short original procedural click and its own temporary source, honoring the existing Zoo effects mute/foreground gain without interrupting animal sounds.
