Implementation

The platform discovery boundary now has separate Windows and Apple adapters. The Objective-C++ Apple bridge browses the declared _lw-playset._udp service, resolves only the enrolled authority, bounds its queues, polls without blocking the Unity frame loop, and closes native handles when done. Public TXT values must match family/world/authority and protocol/content versions. They do not authorize a player: the existing certificate-validated DTLS and independent player credentials remain required.

The iOS client can consume a parent-provisioned USB inbox into an app-owned, nonsynchronizing Keychain item accessible only while the device is unlocked. Only a client enrollment is accepted. It never includes the server's private key or other players' credentials. The inbox requests exclusion from backup and is removed after Keychain storage succeeds. An identical retry is permitted; a different identity cannot silently replace the existing child's enrollment. Physical Keychain/import/update testing is still pending. This is a development provisioning path, not the finished parent pairing screen.

An unpaired iPad update opens the existing solo garden. Paired devices without a reachable authority open a separate offline branch. Existing iPad voice/joystick choices use the same device preference keys in solo and shared play. The old solo save, offline branch and authority checkpoint remain separate; no offline merging is implemented.

After an established shared connection is lost, the paired client disables new shared actions, clears pending inputs and interpolation history, releases its connection and waits for NGO to finish shutting down. It then rediscovers the enrolled authority, reconnects securely, and waits for a fresh authoritative snapshot before enabling input. Retry delays rise from 2 seconds to a 15-second cap. A restarted authority may have a new port and process epoch; the saved family/player identity is retained. Explicit authentication or compatibility rejection stops retries and requests parent help.

The shared foreground adapter suspends discovery/retries when the app backgrounds and restarts them on return. The Windows harness invokes that same adapter to test its behavior; this does not simulate iOS suspension, memory pressure or local-network privacy enforcement. Intentional app shutdown does not start another connection.

Test corrections retained

Two initial rejoin harness attempts stopped before testing reconnection fully. One dropped the bucket at a hardcoded coordinate away from the actual plant; another attempted to address a stationary target as a draggable pointer surface. The corrected harness reads the target position and still drives normal Unity pointer input. The game rules and interaction tolerance were unchanged. Both initial results are retained in the evidence folder; neither is reported as a game pass.

The final native verifier includes local Mach-O function symbols: IL2CPP calls these bridge functions statically, so an exported-symbol-only check would incorrectly reject them. The actual linked functions were verified.

The Mac bridge harness initially requested a separate dns_sd library that the Mac toolchain did not provide. Linking against the normal macOS system libraries corrected the harness; the iOS native application linked successfully independently. The export transfer also handles the Mac's bundled Python 3.9.6, which predates tar extraction filters: it verifies the archive hash and permits only contained regular files/directories before extraction.

Sources and implementation basis

Apple requires an explanation for local-network access and declaration of Bonjour service types. The adapter follows that route instead of implementing raw multicast discovery. Allowed/denied permission behavior must still be tested in the signed app. Apple local-network privacy guidance.

Apple's Keychain API supports adding and retrieving persistent secrets. The code uses device-local accessibility and rejects replacement of an existing identity; that replacement policy is this project's decision. Apple Keychain guidance.

The Unity native plugin uses exported C functions called with DllImport("__Internal"), Objective-C++ and ARC. The export links Security.framework and includes the bridge in UnityFramework. Unity 6000.3 native iOS plugins.

Unity's reconnect guidance requires completed shutdown, resetting client state and handling explicit denials differently from ordinary losses. The implementation checks ShutdownInProgress and retains identity outside transient network client IDs. The installed NGO 2.13.2 source was checked; online 2.13 documentation identifies itself as 2.13.3, and no package was upgraded. Unity reconnecting mid-game.

Reproduce

From the game root in PowerShell:

dotnet run --project Tools/SoloRules.Tests -- LocalData/Verification/new-family-rules --bonjour
uv run --with cryptography python Tools/Test-FamilyLAN.py 74
uv run --with cryptography python Tools/Test-FamilyReconnect.py 74
uv run python Tools/Test-SharedGarden.py 74

For a new export, use a fresh build number with Tools/Build-iPadFamilyLAN.ps1, then Tools/Transfer-iPadFamilyExport.py and Tools/Prepare-iPadSigning.py. The latter prepares the local Mac helper; --check-unsigned compiles without signing or installing. Tools/Verify-iPadNative.py checks the resulting unsigned app and linked bridge functions. Parent-created Windows enrollment can be launched with Tools/Start-FamilyLAN.py; a zero/default port selects an available port for Bonjour to advertise.
